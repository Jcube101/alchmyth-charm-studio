# Contributor Guide

## Project structure

- `src/routes/` contains TanStack file-based pages and server endpoints.
- `src/lib/` contains catalog, pricing, quote, payment, and persistence logic.
- `src/features/store/` contains storefront state and checkout behavior.
- `drizzle/schema.ts` is the PostgreSQL schema.
- `drizzle/migrations/` contains committed migration SQL and generated metadata.
- `tests/e2e/` contains Playwright browser tests.

Use Bun for dependency management and project scripts.

## Development

```sh
bun install
bun run dev --host 0.0.0.0 --port 5000
```

Keep pricing, signatures, provider verification, persistence, and secret access in server-only modules. Browser code may send product identifiers, quantities, options, and provider callback fields, but it must not determine trusted prices or paid state.

Money is stored and exchanged with server integrations as integer paise. Convert to rupees only for display.

## Secrets and environment variables

- Never commit `.env` files, credentials, tokens, webhook URLs, customer data, or uploaded debugging material.
- Use `.env.example` for variable names only.
- Do not add server secrets to `VITE_*` variables; Vite-prefixed values are exposed to browser bundles.
- Access `DATABASE_URL`, Razorpay credentials, and webhook/callback secrets only on the server.
- Log references and state transitions, not customer contact details or provider secrets.
- On Replit, use Secrets for sensitive values and environment variables only for non-secret configuration.

## Database changes

1. Update `drizzle/schema.ts`.
2. Run `bunx drizzle-kit generate`.
3. Review the generated SQL and metadata.
4. Apply migrations to development with `bunx drizzle-kit migrate`.
5. Validate affected persistence and route behavior.
6. Commit the schema, migration SQL, snapshots, and journal together.

Never rewrite or edit an already-deployed migration. Create a new migration for follow-up changes. Do not replace the configured PostgreSQL database with another storage system without explicit approval.

## Generated files

`src/routeTree.gen.ts` is generated by the TanStack Router plugin. Add, rename, or remove route source files under `src/routes/`, then let the development server or build regenerate the route tree. Do not hand-edit generated route definitions.

Drizzle snapshot files and `_journal.json` are generated migration metadata. Review and commit them with their matching migration; do not edit them independently.

Build output such as `.output/`, `.nitro/`, `.tanstack/`, test reports, and browser traces must remain untracked.

## Validation

Run checks appropriate to the change, and run the full set before shipping changes that affect checkout, quotes, persistence, routes, or configuration:

```sh
bun run lint
bunx tsc --noEmit
bun run test
bun run test:e2e
bun run build
```

`bun run format` writes changes. Review its diff before committing.

Playwright starts a temporary server on port 4173. Replit may add that temporary port to `.replit`; remove the generated mapping after tests and retain only real workflow ports.

## Payment and quote safety

- Treat browser prices, totals, references, and success redirects as untrusted.
- Recompute quote and checkout totals on the server from catalog/config data.
- Persist pending orders before calling Razorpay.
- Verify signatures and fetch provider records before marking an order paid.
- Validate provider identity, amount, currency, order status, and captured payment status.
- Keep browser and webhook settlement idempotent and enforce uniqueness in PostgreSQL.
- Return only the minimum confirmation data needed by public pages.
- Preserve quote submission idempotency, rate limits, HTML escaping, and allowed status transitions.

## Git safety

- Do not rewrite published history: no force pushes, destructive rebases, or history purges unless the user explicitly requests and understands the consequences.
- Do not use `git reset --hard`, `git clean`, or broad checkout/restore commands that could remove user work or ignored local files.
- To stop tracking a sensitive/local file while preserving the user's copy, use `git rm --cached`, confirm the file still exists, and add an ignore rule.
- Do not commit `attached_assets/` or local environment files.
- Inspect `git status` and staged changes before completing work. Never revert unrelated changes.
